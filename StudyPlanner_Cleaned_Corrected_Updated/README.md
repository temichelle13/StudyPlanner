# Study Planner

An opinionated foundation for an AI-assisted study planning experience. The project now ships with a fully-articulated front-end layout, resilient API surface, and guardrails that let you plug in data and intelligence features with minimal friction.

## Highlights

- **Modern dashboard layout** – responsive, accessible, and organised into dedicated panels for overview, schedule, tasks, goals, resources, and analytics.
- **Task management workflow** – fully wired form, filters, and offline-friendly interactions that gracefully degrade to sample data when the API is unavailable.
- **Authentication-ready API** – Express routes for registration, login, and profile access with request validation, JWT handling, and consistent error responses.
- **Task API blueprint** – CRUD operations with owner scoping, pagination support, and schema-level indices to prepare for production workloads.
- **Quality guardrails** – centralised error handling, request validation via Joi, async helpers, and sensible defaults for local development.

## Getting started

### Prerequisites

- Node.js 18+
- npm 9+
- MongoDB Atlas cluster or self-hosted MongoDB instance (optional for layout review; required to persist data)

### Installation

```bash
# Clone and install dependencies
cd StudyPlanner_Cleaned_Corrected_Updated
npm install
```

### Environment variables

Create a `.env` file in the project root with at least the following values when connecting to real data:

```bash
PORT=3000
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster-url>/<database>
JWT_SECRET=replace-this-with-a-long-random-string
JWT_EXPIRES_IN=1h
```

If `MONGODB_URI` is not provided, the server will start in offline mode and the UI will display interactive sample data so you can validate the layout quickly.

### Run the application

```bash
# Start the API and serve the static dashboard
npm start

# During development with auto-reload
npm run dev
```

Visit `http://localhost:3000` to explore the dashboard experience.

## API overview

| Method | Endpoint            | Description                                 |
| ------ | ------------------- | ------------------------------------------- |
| POST   | `/api/auth/register` | Register a new account (validates payloads) |
| POST   | `/api/auth/login`    | Authenticate and receive a JWT token        |
| GET    | `/api/auth/me`       | Retrieve the authenticated profile          |
| GET    | `/api/tasks`         | List tasks for the authenticated user       |
| POST   | `/api/tasks`         | Create a task                               |
| PATCH  | `/api/tasks/:id`     | Update a task                               |
| DELETE | `/api/tasks/:id`     | Remove a task                               |

> **Note:** Task endpoints require a bearer token generated by the authentication routes. The front-end gracefully falls back to sample data when requests are unauthorised.

## Project structure

```
public/                # Front-end layout, styles, and scripts
controllers/           # Route handlers for tasks and users
middleware/            # Auth, validation, and error handling helpers
models/                # Mongoose models with indexes and virtuals
routes/                # Express route definitions
validators/            # Joi schemas for request payloads
utils/                 # Async helper utilities
```
